TC 중요도 (TC 관리 영역 · 저장값 P1/P2/P3)
  • P1 핵심 — 결제/재고/데이터 정합성 등 서비스 핵심 플로우
  • P2 주요 — 주요 기능 및 주요 사용자 경험 검증
  • P3 일반 — 보조 기능, UI 세부 검증, 미확정 케이스
결함 심각도 (결함 관리 영역 · 저장값 Critical/Major/Minor)
  • Critical 치명 — 서비스 중단, 결제 오류 등 치명적 결함
  • Major 주요 — 핵심 기능 오동작, 데이터 유실 위험 결함
  • Minor 경미 — 단순 UI 틀어짐, 텍스트 오탈자 등 경미한 결함
영역별 적용표 ○ 적용 · △ 일부 적용 · – 미적용
영역모듈TC 중요도수행 상태실행 결과검색적용 방식
KPI 카드 · 확인이 필요한 항목–––––항상 프로젝트 전체 기준 (필터로 바뀌지 않음)
모듈별 TC 수행현황○–○○○조건을 모두 만족하는 모듈 행만 표시 (행 단위로 걸러냄). 검색은 모듈명·코드
TC 우선순위 / 분포○△–––모듈 선택 시 도넛 합계와 수행/미수행 타일이 그 모듈 기준으로 재계산. TC 중요도는 숫자를 바꾸지 않고 선택 외 구간만 흐리게
결함 관리○–––○조건에 맞는 결함만 목록에 표시. 모듈은 결함의 TC ID(TC_모듈코드_번호)로 판정. 결함 심각도는 카드 안 자체 필터에서 선택하며 상단 필터와 AND. "총 N건"은 필터와 무관한 전체 건수
최근 실행 이력○––○○모듈 선택 시 그 모듈의 이력만. 실행 결과는 그 실행에서 해당 결과가 1건 이상 있었던 이력만 (Fail → Fail이 있었던 실행)
바로가기 · AI Assistant–––––필터와 무관
  • "수행됨" = Pass + Fail + N/A + N/T (미실행만 제외) — 4000 대시보드의 수행율 정의와 같습니다.
  • 수행 건수·결과(Pass/Fail/N/A/N/T/미수행)는 모듈별 TC 정본의 현재 실행결과 기준이며, TC 뷰어(HTML)의 통계표와 같은 값입니다. 실행 이력과 날짜별 진척율만 그 실행 시점의 기록(스냅샷)입니다.
  • 결함 관리 카드의 자체 필터는 위 필터와 모두 만족(AND)해야 표시됩니다. 상태의 미해결 = '완료'를 제외한 모든 상태.
  • 상단 KPI 카드와 "지금 확인이 필요한 항목"은 필터와 무관하게 프로젝트 전체 기준입니다. Critical 결함 = 상태가 '완료'가 아닌 심각도 Critical 결함.

      섞여 있어도 됩니다.

      .json — TC 항목 배열([{"tcId":"...", "majorCategory":"...", ...}, ...])
      또는 캐노니컬 파일 전체({"meta":{...},"items":[...]}, TC 뷰어의 "JSON 저장"이
      만드는 형식 그대로) — 필드명은 엑셀 헤더가 아니라 tcId/majorCategory/steps/expected 같은
      캐노니컬 스키마 이름을 그대로 씁니다.

      두 형식 모두 TC ID가 이미 등록된 값이면 수정, 비어있으면 대분류를 기준으로 신규 추가되며,
      값이 채워진 칸/필드만 반영되고 나머지는 기존 값을 그대로 둡니다.

      단, TC ID가 같아도 대/중/소분류·테스트항목 중 값이 있는 게 서로 다르면 같은 TC의 수정이
      아니라 우연히 ID만 겹친 별개 케이스로 보고, 기존 TC는 그대로 둔 채 새 TC ID로 분리 생성합니다
      (결과 화면에 어떤 항목이 분리 생성됐는지 안내됩니다).
