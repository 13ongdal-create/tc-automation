### [★ 프로젝트 단위 맥락 및 회귀 자산 재사용/일원화 원칙 (Regression Asset Management)]
1. **모드 자동 판별 (Create vs Update/Expand)**:
   * **[신규 생성 모드]**: 대상 URL/모듈 첫 분석 시 전체 매트릭스를 신규 구축합니다.
   * **[추가/수정 모드]**: 사용자가 **"기존 TC 리스트"**나 **"추가/수정 모듈 요구사항"**을 함께 제시하는 경우, 기존 TC 자산을 파괴하지 않고 **[유지] / [정책 수정(Update)] / [신규 추가(Add)]**로 분류하여 기존 파일에 통합된 단일 통합 TC 리스트(Single Source of Truth)를 도출해야 합니다.
2. **모듈별 체계적 TC ID 네이밍 규격**:
   * 프로젝트 내 TC ID 중복을 방지하기 위해 도메인/모듈별 고유 Prefix를 엄격히 적용하십시오.
   * `TC_PD_` (상품상세), `TC_CRT_` (장바구니), `TC_ORD_` (주문/결제), `TC_PR_` (프로모션/혜택), `TC_MY_` (회원/마이페이지), `TC_CLM_` (취소/반품/교환)
3. **변경 영향도 분석 (Impact Analysis) 자동 반영**:
   * 특정 모듈 추가/수정 시, 연결된 타 모듈(예: 결제 추가 ➔ 장바구니 수식, 취소/환불 정산 영향)의 회귀 테스트(Regression Test, P1/P3) 시나리오를 자동으로 함께 보완하십시오.
4. **정책 변경 이력 및 회귀 태깅**:
   * 기존 정책 변경으로 수정된 TC의 경우 기대 결과 란에 **`[정책변경: v1.0 ➔ v1.1]`** 형태의 태그를 명시하여 변경 이력을 추적 가능하게 하십시오.

### [이커머스 14대 표준 도메인 범주 및 QA 체크포인트 매핑 스펙 (Taxonomy Spec)]

1. **회원유형**: 비회원, 오프라인회원, 온라인회원, 통합회원, 임직원, 간편회원, 법인, 외국인
2. **공급방식**: 자사 직접판매, 입점 파트너사(오픈마켓/직매입) 판매
3. **상품속성**: 일반상품, 옵션상품, 세트상품, 증정품
4. **오퍼/쿠폰/프로모션/행사대상**: SALE/즉시할인, 쿠폰(상품/장바구니/난수/배송비), 카드사 할인, 대상 분기
5. **배송유형/배송비**: 택배, 당일, 새벽, 픽업(매장/편의점), 예약 / 유료, 조건부 무료, 무료, 도서산간 추가비, 클레임 배송비
6. **결제수단/보조결제**: 간편결제(Npay, 카카오, 삼성, 토스, 쿠페이, 페이코 등), 카드사(신한, 국민, 삼성, 현대 등), 휴대폰, 계좌이체, 가상계좌, 예치금 / 포인트, 마일리지
7. **세금/클레임/귀책**: 과세, 면세, 관세 / 취소(전체/부분), 반품(전체/부분), 교환(전체/부분) / 고객 귀책 vs 당사/판매자 귀책

### [이커머스 고위험 실무 검증 필수 시나리오 (Mandatory Edge Cases)]

* **① 장바구니 (Cart) 영역**: 동일 옵션 중복 담기 수량 합산(`quantity + N`), CRUD 기본 상태, 최소/최대 수량 한도 제어, 카트 내 상품 [품절/판매중지] 딤드 전환, 크로스 플랫폼(App ↔ Web) 실시간 동기화.
* **② 프로모션 & 쿠폰/포인트 영역**: 할인 적용 우선순위 순서(`상품가 ➔ 쿠폰 ➔ 적립금/포인트`), 행사 기간 유효성 vs 만료 처리.
* **③ 주문 & 결제 (Order & Checkout) 영역**: 사전조건 내 회원 유형 및 실제 재고 수량 수치 명시, 동시성 재고 선점 경합 과판매 차단, 결제 세션 타임아웃(3분 초과) 선점 재고 롤백, 배송지 가변 변경 시 추가 운임/새벽배송 비동기 전환.
* **④ 취소/반품 정산 (Cancel & Return) 영역**: 조건부 무료배송 부분 취소/반품 시 차기 배송비 차감 및 비율 쿠폰/적립금 부분 복원 수식.

### [테스트 케이스 작성 표준 기술 규격 (TC Writing Guidelines)]

#### 1. 테스트 유형 (6번 컬럼 5대 허용 규칙)
* **`UI`**: 화면 렌더링, 색상 코드, 레이아웃 정렬, CSS 하이라이팅, 마이크로 애니메이션, 팝오픈 뷰 모션.
* **`기능`**: 버튼 인터랙션, 드롭다운 옵션 조작, 탭 내비게이션 전이, 검색 바 입력 작동, 수량 조절 등.
* **`API`**: 백엔드 REST API 통신 상태코드(200, 400, 401, 500 등), Request/Response JSON Payload 파라미터 무결성, DB 상태 값 동기화.
* **`성능`**: 로딩 속도, Lazy Loading, 레이턴시, Web Vitals CLS(누적 레이아웃 비틀림 < 0.1) 최적화, OOM/App Crash 방호.
* **`데이터`**: 금액 수식 산출, 할인율 반올림 계산, 고시 표기법 준수 여부, OG 메타 태그 무결성.

#### 2. 5대 TC 세부 가이드북 (High-Precision Procedure Specs)
* **① UI TC**: 진입 경로 명명화(`홈 > 카테고리 > 상세`), 시각 수치 지정(`Hex 코드`, `딤드`, `천단위 콤마`).
* **② API TC**: Web DevTools / Charles Proxy 패킷 캡처 명시, HTTP Status Code 및 Request/Response JSON Payload 대조.
* **③ Network TC**: DevTools Slow 3G/Offline 또는 기내모드 셋업, Broken Image/Crash 차단 및 Skeleton UI / 예외 모달 표출 검증.
* **④ 상태 전이 (State Transition) TC**: 초기 세팅 ➔ 트리거 ➔ F5 없이 AJAX DOM 비동기 실결제액 차감 환산 표출.
* **⑤ 회귀 (Regression) TC**: 비동기 배너/광고 마운트 시 `DevTools > Performance > Web Vitals CLS < 0.1` 유지하여 레이아웃 비틀림 방호.

#### 3. [★ 핵심] 기대 결과 작성 및 정책 검증 원칙 (Policy Validation Principle)
* **임의 추정 엄격 금지**: 실 서비스 동작이나 백엔드 처리 로직이 100% 명확히 확인되지 않은 경우, AI가 임의로 결론("정상 동작함", "정상 처리됨")을 추측하여 작성하는 것을 엄격히 금지합니다.
* **`[확인필요]` 표기 의무화**: 정책이 불명확하거나 실측 검증이 필요한 항목은 기대 결과 란에 반드시 **`[확인필요]`** 태그를 상단에 명시하고, 실제 QA 착수 전 정책 담당자(PO/PM/기획자)에게 확인받아야 할 질문 항목을 구체적으로 기재하십시오.

### [Phase 4 HTML 웹 앱 디자인 & 기능 스펙 규격]

#### 1. 테마 스위처 & UI 컴포넌트
* **CDN 라이브러리**: Pretendard 폰트, Tailwind CSS, FontAwesome 6.4.0 아이콘 필수 탑재.
* **[필수] 실시간 테마 전환 토글 기능 (Theme Switcher)**:
  * HTML 상단 헤더 우측에 **`[ ☀️ 라이트 모드 / 🌙 다크 모드 ]` 토글 버튼** 탑재 (`toggleTheme()`).
  * 버튼 클릭 시 페이지 전체(`body`), 카드 패널, 테이블, 텍스트, 검색바, 모달의 스타일이 **다크 모드 ↔ 라이트 모드로 실시간 즉시 스타일링 교체**되어야 함.
* **상단 헤더**: 타이틀(`[대상 사이트명] QA 테스트 매트릭스 v8.0`), `[테마 토글]` 버튼, `[테스트 계정 매트릭스]` 버튼, `[User Flow Map]` 버튼, `[타겟 스토어 바로가기]` 버튼.
* **KPI 통계 카운터 카드**: `전체 테스트 케이스`, `P1 (Critical)`, `P2 (Major)`, `P3 (Minor/예외·회귀)`, `검증 도구 셋업 상태` 5개 카드 (JS 배열 수치와 100% 실시간 연동).
* **툴바 및 검색**: 우선순위 드롭다운, 중분류 드롭다운, 플랫폼 드롭다운, 키워드 실시간 검색 바.
* **모달 팝업 2종**:
  1. `openPersonaModal()`: 4대 계정별 세팅 요건 팝업.
  2. `openFlowModal()`: 대상 서비스 맞춤 5단계 User Flow 시각화 팝업.

#### 2. 하단 11개 스키마 컬럼 표 노출 스펙 (No Scroll Table View)
* **테이블 내부 스크롤 제거**: 테이블 컨테이너의 고정 높이(`max-height`) 및 내부 세로 스크롤을 완전히 제거하고, 전체 TC 리스트가 페이지 스크롤을 통해 한눈에 시원하게 펼쳐지도록 구현하십시오.
* **11개 전체 컬럼 유지**:
  1. `1. TC ID` | 2. `2. 대분류` | 3. `3. 중분류` | 4. `4. 소분류` | 5. `5. 플랫폼` | 6. `6. 유형 (UI/기능/API/성능/데이터)` | 7. `7. 테스트 항목 (시나리오)` | 8. `8. 우선순위 (P1/P2/P3)` | 9. `9. 사전 조건 (FO 계정 & 툴)` | 10. `10. 테스트 수행 절차` | 11. `11. 기대 결과`
* **텍스트 정렬 및 스타일 규칙**:
  * **10번 수행 절차**: 넘버링(`1)`, `2)`, `3)` 또는 `1.`, `2.`, `3.`)을 기준으로 한 줄씩 깔끔하게 줄바꿈(`whitespace-pre-line`) 처리.
  * **11번 기대 결과**: `[확인필요]` 키워드가 포함된 문구는 **적색 폰트(#EF4444, Bold) 및 은은한 적색 배경 뱃지 스타일**을 자동 적용할 수 있는 자바스크립트 렌더링 로직(`formattedExpected`) 포함.

#### 3. 전수 검증 시나리오 작성 원칙
* **수치 제한 없는 전수 도출**: 최소 30개 이상 ~ 도출 가능한 최대 경우의 수(Positive/Negative/Boundary/Exception)를 축약이나 줄임표(`...`) 없이 자바스크립트 `testCases` 배열 내에 100% 완전한 텍스트로 기입하십시오.
