# 대시보드 팀 공유 셋업 가이드

이 문서는 로컬(3top PC)에서만 상시 구동되던 QA Automation 대시보드를, 원격/외부 팀원도 각자
자신의 PC에서 **자신의 Claude 계정**으로 동일하게 사용할 수 있게 하는 방법을 안내합니다. 서버를
인터넷에 노출하지 않고, 각자 로컬에서 대시보드를 실행하고 데이터는 git으로 동기화하는 방식입니다.

## 사전 준비 (팀원 각자)

1. **GitHub 저장소 접근 권한**: `github.com/13ongdal-create/tc-automation` — Collaborator로
   초대받아야 합니다.
2. **Git** 설치
3. **Node.js 18 이상** 설치
4. **Claude Code CLI** 설치 후 본인 개인 Claude 계정으로 로그인 (`claude` 명령을 한 번 실행해
   로그인 여부 확인)

## 1) 저장소 clone

```bash
git clone https://github.com/13ongdal-create/tc-automation.git
cd tc-automation
```

## 2) 대시보드 실행

```bash
cd dashboard
npm install
npm start
```

최초 실행 시 `dashboard/.dashboard-password` 파일이 자동 생성됩니다 (git 비대상 — 본인 로컬에만
존재). 이 파일을 열어 로그인 비밀번호를 확인하세요. 원하면 `DASHBOARD_PASSWORD` 환경변수로 직접
지정할 수도 있습니다.

## 3) 접속

기본은 평문 HTTP입니다(인증서 파일이 없으면 자동 폴백). HTTPS로 쓰고 싶으면 먼저 인증서를
생성하세요(감지되는 이 PC의 모든 외부용 IPv4가 자동으로 포함됩니다):
```bash
bash dashboard/scripts/gen-cert.sh
```
그다음 `npm start`(또는 이미 켜져 있다면 재시작) 후 브라우저에서 `https://localhost:4000` 접속.
자체서명 인증서 경고가 뜨면 "고급" → "계속 진행"으로 넘어가면 됩니다.

## 4) 꼭 알아둘 점

- 이 대시보드는 **본인 PC에서만** 실행됩니다. 채팅 패널이 내부적으로 실행하는 `claude` CLI는
  본인 계정 기준으로 동작하므로, 파일 수정/커밋도 본인 이름으로 남습니다. 시작 전 로컬 git
  설정을 본인 정보로 맞춰두세요:
  ```bash
  git config user.name "본인 이름"
  git config user.email "본인 이메일"
  ```
- 데이터(TC/결함/실행이력)는 별도 서버·DB가 아니라 **git 저장소 안의 파일**입니다. 따라서 작업
  시작 전 반드시 최신 상태로 `pull` 받아야 남의 작업과 어긋나지 않습니다.

## Git 브랜치 전략 (동시 작업 충돌 방지)

이 저장소는 프로젝트 폴더(`project/{프로젝트명}`)가 서로 완전히 격리되어 있습니다
(AGENTS.md 16항 "프로젝트 간 내용 격리 원칙"). 브랜치도 이 구조에 맞춰 나누면, 여러 사람이
동시에 작업해도 충돌이 거의 발생하지 않습니다.

### 규칙

1. **작업 시작 전**
   ```bash
   git checkout main
   git pull
   ```
2. **작업 범위에 맞는 브랜치 생성**
   - 특정 프로젝트 작업: `{프로젝트명}/{작업요약}`
     예) `git checkout -b 데모사이트/def011-recheck`
   - 공통 규칙·대시보드 코드 작업: `common/{작업요약}`
     예) `git checkout -b common/branch-policy`
3. **평소처럼 작업** — Claude Code의 Phase 4/8 자동 커밋도 브랜치 위에서 그대로 동작합니다.
   AGENTS.md 18항의 "git add는 해당 프로젝트 경로만" 규칙은 브랜치 작업 중에도 동일하게
   지킵니다.
4. **작업 마무리 후 푸시**
   ```bash
   git push -u origin 데모사이트/def011-recheck
   ```
5. **GitHub에서 `main`으로 Pull Request 생성**
   - 프로젝트 폴더만 건드린 브랜치는 다른 프로젝트와 겹칠 일이 거의 없어 바로 병합해도 안전합니다.
   - `agents-config/`, `CLAUDE.md`, `dashboard/` 등 **공통 파일을 건드린 브랜치**는 다른
     사람이 동시에 같은 파일을 수정 중일 수 있으니, 병합 전 팀 채널에 알리고 확인받은 뒤
     병합합니다.
6. **병합 후** 각자 다시 `git checkout main && git pull`로 최신화하고 다음 작업을 시작합니다.

### 왜 충돌이 줄어드나

- 프로젝트별 폴더가 이미 격리되어 있어, 브랜치를 프로젝트 단위로 나누면 병합 시 대부분
  자동으로 깨끗하게 합쳐집니다.
- 실제 충돌 위험은 **같은 프로젝트를 두 명이 동시에 작업**하거나, **공통 규칙 파일을 동시에
  수정**할 때만 발생합니다 — 이 두 경우만 팀 채널로 조율하면 충분합니다.
