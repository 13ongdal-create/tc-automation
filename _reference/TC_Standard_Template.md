# QA 테스트 케이스(TC) 작성 기본 규칙 및 템플릿

본 문서는 고품질의 QA 테스트 케이스(TC)를 자동으로 일관성 있게 생성하기 위한 **기본 규칙(Rules)**과 **표준 템플릿(Template)**을 정의합니다. 앞으로 모든 TC 생성은 본 문서의 기준을 따릅니다.

---

## 1. TC 작성 기본 규칙 (Core Rules)

### 1-1. 추측 금지 (No Speculation)
* 모든 TC는 기획서, 화면설계서, API 스펙 등 **명확한 기준문서에 근거**해야 합니다.
* 기준문서가 없는 경우, "일반적으로 이럴 것이다"라는 추측을 배제하고 반드시 **`[확인필요]` 태그**를 제목에 부착하여 불확실함을 명시합니다.

### 1-2. 초보자도 실행 가능한 구체성 (Specificity)
* **사전조건(Preconditions):** 테스트에 '반드시' 필요한 조건만 나열합니다. (예: 쿠폰 테스트가 아니라면 계정의 보유 쿠폰 개수 등은 생략)
* **테스트 절차(Procedures):** 화면 진입부터 클릭, 텍스트 입력까지 Step-by-Step으로 구체적으로 작성합니다. 
* **기대결과(Expected Results):** "정상 작동한다"와 같은 모호한 표현을 금지하고, 화면에 노출되는 **정확한 문구, 색상 변화, 팝업 유무, 버튼 활성/비활성 상태** 등을 구체적으로 서술합니다.

### 1-3. 시각적 수치 및 미확정 스펙 분리 표기
* CSS 수치(Hex 색상코드 등)나 기획 미확정 사항은 기대결과 본문과 섞지 않고, 하단에 `*` 기호와 함께 별도로 분리하여 작성합니다.

## 2. 기본 TC 템플릿 (16 Columns Schema)

| No | 컬럼명 | 작성 가이드 및 예시 |
|---|---|---|
| 1 | TC ID | `TC_{분류명}_{순번}` (예: TC_SIGNUP_001) |
| 2 | 대분류 | 상품/구매프로세스/클레임/회원/탐색/기타 등 |
| 3 | 중분류 | 모듈명 (예: 회원가입, 로그인, 장바구니 등) |
| 4 | 소분류 | 세부 기능명 (예: 약관동의, 정보입력 등) |
| 5 | 플랫폼 | PC / APP / PC+APP |
| 6 | 유형 | UI / 기능 / API / 성능 / 예외 |
| 7 | 테스트 항목(시나리오) | 검증하고자 하는 핵심 목적 한 줄 요약 (불확실 시 `[확인필요]` 접두) |
| 8 | 기준문서 | 참고한 기획서 파일명 및 페이지 번호 (없으면 `-`) |
| 9 | 우선순위 | P1 (크리티컬) / P2 (주요) / P3 (마이너 및 확인필요 항목) |
| 10 | 사전조건 | 테스트 시작 전 필요한 데이터 및 상태 (번호 매김) |
| 11 | 테스트 수행 절차 | 행동 단위로 번호를 매겨 구체적 서술 |
| 12 | 기대 결과 | 절차 수행 후 나타나야 하는 명확한 시스템 반응 |
| 13 | 실행결과 | Pass / Fail / Blocked / N/A |
| 14 | 담당자 | 테스트 수행자 |
| 15 | 이슈내용 요약 | 버그 발생 시 간단한 증상 요약 |
| 16 | 이슈링크 | Jira 등 버그 트래킹 티켓 링크 |

## 3. Best Practice (TC 작성 예시)

### [예시] UI/기능 테스트 (예외 처리)
* **테스트 항목:** `[확인필요]` 기 가입된 아이디(이메일) 입력 시 중복 경고 문구 확인
* **사전조건:** 
  1) 기존에 가입 완료된 활성 계정 이메일 준비 (예: `already_exist@test.com`)
* **테스트 수행 절차:**
  1) 비회원 상태로 회원가입 > 정보입력 화면 진입
  2) 이메일 입력란에 `already_exist@test.com` 입력 
  3) 이메일 입력란 밖의 빈 공간을 클릭(포커스 아웃)
* **기대 결과:**
  이메일 입력란 하단에 "이미 가입된 이메일입니다." 경고 문구가 노출되며, 다음 단계 버튼은 비활성화 상태가 유지된다.
  * *확인필요: 경고 텍스트 색상 (예: Hex #FF0000)*

## 4. TC 자동 생성 프로세스 (Workflow)

1. **Rule & Template 로드:** AI는 항상 본 `TC_Standard_Template.md`의 규칙과 양식을 기준으로 삼습니다.
2. **Phase 1~3 (시나리오 검토):** 타겟 화면/기획서를 바탕으로 테스트할 '항목(시나리오 리스트)'을 먼저 도출하여 사용자 승인을 받습니다.
3. **Phase 4 (상세 TC 및 HTML 뷰어 생성):** 승인된 시나리오를 바탕으로 16개 컬럼의 상세 TC를 작성하고, 이를 관리할 수 있는 Interactive HTML 뷰어로 추출합니다.
