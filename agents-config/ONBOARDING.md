# tc-automation 프로젝트 온보딩 가이드

이커머스 QA TC(테스트케이스) 자동 생성/실행/결함관리 시스템 "큐돌이"의 작업 환경 안내입니다.
Claude Code(클로드 코드)를 처음 다시 열거나, 다른 사람이 이 작업을 이어받을 때 참고하세요.

> **2026-08-24부터 Slack bot(`@큐돌이`) 사용을 종료했습니다.** QA 자동화(TC 생성/테스트 실행/결함조회 등) 자체는 계속 진행하며, 인터페이스만 **터미널 또는 IDE(Claude Code 직접 세션)**로 바뀌었습니다. 이 문서의 4~5번(Slack 브릿지 서버 관련)은 참고용으로 남겨두었을 뿐 더 이상 적용되지 않습니다.

## 1. 프로젝트 구조 한눈에 보기

```
D:\tc-automation\                 <- 이 프로젝트 전체의 루트
├── agents-config\                <- 규칙/스킬 저장소 (AGENTS.md, SKILL.md) — 별도 git 저장소
├── slack-bridge\                 <- Slack 연동 서버 — 별도 git 저장소 (2026-08-24부로 미사용, 4~5번 참고)
├── _template\                    <- 신규 프로젝트 온보딩용 빈 폴더 틀
├── {프로젝트명}\                  <- 프로젝트별 폴더 (예: 데모사이트) — Policy/SB/Requirements/Analysis/TC
└── ...
```

- **AGENTS.md** (`agents-config\AGENTS.md`)와 **SKILL.md** (`agents-config\skills\qa-test-case-generator\SKILL.md`)가 클로드가 따르는 모든 규칙의 원본입니다. 클로드 코드를 이 폴더 구조 안에서 실행하면 별도 설명 없이 이 문서들을 읽고 동일하게 동작합니다.
- 실제 작업 결과(TC 데이터, 뷰어, PRD 등)는 전부 **git으로 커밋되고 GitHub에 push까지** 되어 있습니다. 대화가 끊기거나 PC가 꺼져도 파일과 이력은 그대로 보존됩니다.

## 2. PC 재부팅 후 이어서 작업하기

**작업 자체는 파일(git 저장소)에 있으므로 재부팅해도 사라지지 않습니다.** 아래 두 가지 방법으로 이어갈 수 있습니다.

### 방법 A — 이전 대화를 그대로 이어가기
1. 터미널(PowerShell)을 엽니다.
2. 아래 명령으로 이동합니다:
   ```
   cd D:\tc-automation\agents-config
   ```
3. 클로드 코드를 이어가기 모드로 실행합니다:
   ```
   claude --continue
   ```
   (가장 최근 대화를 그대로 이어갑니다.) 여러 대화 중 고를 땐:
   ```
   claude --resume
   ```

### 방법 B — 새 대화로 시작 (그래도 규칙은 동일하게 적용됨)
1. 같은 폴더(`D:\tc-automation\agents-config`)에서 그냥 `claude`만 실행해도, AGENTS.md/SKILL.md를 읽어 동일한 규칙으로 동작합니다.
2. 예전 대화 맥락이 필요하면 "데모사이트 프로젝트 이어서 진행해줘"처럼 프로젝트명을 알려주면 됩니다 — 실제 데이터는 `데모사이트\TC\` 등에 그대로 있습니다.

## 3. 다른 Claude 계정으로 작업 이관하기

| 구성요소 | 계정에 종속? | 이관 방법 |
|---|---|---|
| AGENTS.md/SKILL.md, TC 데이터, 뷰어 | 아니오 (git) | GitHub 저장소(`tc-automation`, `agents-config`)에 새 계정을 협업자로 추가 → `git clone` 후 그 폴더에서 클로드 코드 실행 (`slack-bridge`는 2026-08-24부로 미사용이라 필수 아님) |
| 이번 세션에서 쌓인 자동 메모리(피드백/선호도) | 예 (이 PC의 로컬 파일) | git에는 없음. 이 온보딩 문서가 그 역할을 대신합니다 |
| 대화 이력 자체 | 예 (이 PC/이 계정 로컬) | 다른 계정에서 그대로 열 수 없음 — 다만 git + 이 문서만 있으면 이어가는 데 문제 없음 |
| 노션 접근 권한 | 예 | 새 계정을 해당 노션 워크스페이스에 멤버로 초대 필요 |
| 발행된 뷰어 Artifact 링크 | 예 (기본 비공개) | 공유 메뉴로 공개 전환, 또는 새 세션에서 로컬 HTML을 다시 발행(파일은 git에 있어 재발행 가능) |
| Slack 봇 토큰 등 비밀값(`.env`) | git에 없음(의도적 제외) | 2026-08-24부로 Slack bot 미사용 — 이관 불필요 |

**핵심**: GitHub 저장소 접근 권한만 주면, AGENTS.md/SKILL.md가 규칙을 그대로 재현해주기 때문에 새 계정에게 처음부터 다시 설명할 필요가 거의 없습니다.

## 4. Slack 브릿지 서버 — 수동으로 재시작하는 방법 (초보자용, 현재 미사용)

> ⚠️ **2026-08-24부로 Slack bot 사용을 종료해 이 섹션은 현재 적용되지 않습니다.** Slack을 다시 사용하게 될 경우를 대비해 참고용으로 남겨둡니다.

Slack 봇(`@큐돌이`)이 응답하지 않을 때, 아래 순서로 재시작하면 됩니다.

### 4-1. PowerShell 열기
- 시작 메뉴에서 "PowerShell" 검색 → 실행 (관리자 권한 필요 없음, 일반 실행)

### 4-2. 재시작 스크립트 실행
```powershell
cd D:\tc-automation\slack-bridge
.\restart-slack-bridge.ps1
```
- 화면에 `tc-automation Slack Bridge를 시작했습니다 (PID ...)` 가 뜨면 성공입니다.
- 만약 `실행할 수 없습니다` 같은 보안 오류가 뜨면 아래처럼 한 번만 실행 정책을 풀어주면 됩니다:
  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
  ```
  (예/전체 허용 등을 물으면 `Y` 입력)

### 4-3. 개별 명령도 가능합니다
- **중지만**: `.\stop-slack-bridge.ps1`
- **시작만**: `.\start-slack-bridge.ps1` (이미 실행 중이면 자동으로 감지하고 중복 실행하지 않습니다)
- **로그(대화 기록) 실시간으로 보기**:
  ```powershell
  Get-Content .\server.log -Tail 20 -Wait
  ```
  (멈추려면 `Ctrl + C`)

### 4-4. 잘 안 될 때
- `slack-bridge.pid` 파일을 열어 안에 적힌 번호(PID)를 확인하고, 작업 관리자(Ctrl+Shift+Esc)에서 "세부 정보" 탭 → 같은 PID의 `node.exe`를 찾아 직접 종료한 뒤 다시 4-2를 실행하세요.

## 5. Slack 브릿지 서버 — 재부팅 시 자동 시작 (현재 미사용)

> ⚠️ **2026-08-24부로 Slack bot 사용을 종료했습니다.** 아래 자동 시작 설정 자체는 계속 걸려있어 서버가 백그라운드로는 계속 켜지지만(무해함), 더 이상 TC 생성/테스트 실행의 트리거로 사용하지 않습니다. 완전히 끄고 싶다면 맨 아래 "자동 시작을 끄고 싶다면"을 참고하세요.

**2026-08-21부터 자동으로 켜지도록 설정해두었습니다.** 별도 관리자 권한 없이 동작하는 "Windows 시작프로그램" 방식을 사용했습니다.

### 어떻게 동작하나요?
- 파일 위치: `C:\Users\3top\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\start-slack-bridge.bat`
- Windows는 이 폴더 안의 파일들을 **로그인할 때마다** 자동으로 실행합니다.
- 이 파일은 조용히(창 없이) `slack-bridge\start-slack-bridge.ps1`을 실행해 브릿지 서버를 백그라운드로 켭니다.
- **이미 실행 중이면 중복으로 켜지지 않습니다** (`slack-bridge.pid` 파일로 확인 후 건너뜀).

> ⚠️ 참고: 이 설정 이전에 수동으로(터미널에서 직접) 켜둔 서버는 PID 파일이 없어서, 다음 재부팅부터 이 자동 시작 방식이 정상적으로 자리를 잡습니다. 지금 당장은 그대로 두시면 됩니다 — 별도 조치 필요 없습니다.

### 잘 켜졌는지 확인하는 방법
1. PC를 재부팅하고 로그인합니다.
2. 1분 정도 기다린 뒤 PowerShell을 열고:
   ```powershell
   Get-Content D:\tc-automation\slack-bridge\server.log -Tail 10
   ```
3. `Now connected to Slack` 같은 문구가 보이면 정상입니다.
4. Slack에서 `@큐돌이`에게 짧게 멘션해보고 반응이 오는지 확인해도 됩니다.

### 자동 시작을 끄고 싶다면
아래 파일을 삭제하면 됩니다 (관리자 권한 필요 없음):
```
C:\Users\3top\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\start-slack-bridge.bat
```
탐색기 주소창에 `shell:startup`을 입력하면 이 폴더로 바로 이동합니다.

## 7. Slack 대신 터미널/IDE로 요청하는 방법 (2026-08-24 추가)

Slack bot(`@큐돌이`) 사용을 종료하면서, 예전에 Slack 슬래시커맨드로 하던 일들은 이제 **`D:\tc-automation\agents-config` 폴더에서 클로드 코드 세션을 열고 자연어로 직접 요청**하면 됩니다. AGENTS.md/SKILL.md 규칙은 인터페이스와 무관하게 동일하게 적용되므로, 문구만 아래처럼 바꿔서 요청하면 됩니다.

| 예전 Slack 방식 | 지금 터미널/IDE에서 요청하는 방법 |
|---|---|
| `/tc-generate 프로젝트=데모사이트 ...` | "데모사이트 프로젝트 {모듈/기능}에 대해 TC 생성해줘" |
| (자동화 코드 실행을 Slack 스레드에서 요청) | "{프로젝트명} {모듈} 테스트 실행해줘" / "테스트 수행해줘" |
| `/tc-defects 프로젝트=데모사이트` | "데모사이트 결함 현황 보여줘" |
| Slack 스레드에서 "DEF_001 담당자를 홍길동으로 지정해줘" | 같은 문구 그대로 터미널/IDE 세션에서 요청 (동작은 동일, AGENTS.md 20-4항) |
| Slack이 실패 스크린샷을 스레드에 자동 첨부 | 실패 보고 시 클로드가 `Read` 도구로 스크린샷을 직접 열어 응답에 보여줌 (AGENTS.md 19항) |

**참고**: `claude --continue`/`claude --resume`(2항)로 이전 대화를 이어가거나, 새 대화를 열어도 같은 폴더에서 실행하면 규칙이 동일하게 적용되므로 프로젝트마다 매번 규칙을 다시 설명할 필요가 없습니다.
