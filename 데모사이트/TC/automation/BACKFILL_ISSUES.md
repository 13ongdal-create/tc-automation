# PD 모듈 자동화 백필 — 판단 기록 (2026-08-24)

TC/automation/tests/PD.spec.js에 미커버 45건(TC_PD_032~145 중 45개)의 자동화 코드를 신규 작성하고 실행하는 과정에서 발견한, 사용자 확인이 필요하거나 애매했던 판단들을 기록한다. 지시에 따라 각 항목은 판단/조치까지 마치고 계속 진행했다.

## PD

- **TC_PD_006/009/016/019 (자동화 코드는 있으나 캐노니컬 JSON에 해당 TC 없음)**: `PD.spec.js`에 이미 존재하던(이번 백필 대상 아닌) 테스트인데, `데모사이트_TC_PD.json`에는 대응하는 tcId 레코드가 없다. 오늘 미커버 45건(JSON엔 있는데 자동화가 없던 케이스)과 정반대 유형의 데이터 정합성 문제. 이번 작업 범위 밖이라 결과 반영 대상에서 제외했고, JSON에 없으므로 어떤 TC 결과에도 영향 없음. → **조치**: 그대로 두고 기록만 남김. 후속 정리(레코드 신설 또는 자동화 코드 삭제) 필요.
- **`gotoAnyProduct()` 헬퍼의 네비게이션 대기 방식이 신뢰할 수 없음**: `waitForLoadState('load')`가 Next.js 클라이언트 라우팅(SPA) 전환에서 새 'load' 이벤트를 못 잡아 간헐적으로 카테고리 목록 페이지에 남은 상태로 다음 단계가 진행되는 플레이키가 있었음(TC_PD_006 등에서 재현). → **조치**: `page.waitForURL('**/products/**')`로 교체(공유 헬퍼라 이 함수를 쓰는 TC_PD_001~030 계열 전체에 적용됨). 수정 후 TC_PD_006은 안정적으로 통과 확인.
- **TC_PD_009/016/019는 위 수정 후에도 여전히 불안정**: "+1" 버튼/"상세정보"·"리뷰" 탭이 실제로는 `<button>` role이 아니거나(탭 텍스트가 일반 텍스트 노드), 매번 다른 상품으로 진입해 속성 유무가 갈리는 것으로 추정. JSON에 없는 orphan 테스트라 이번 범위에서 더 파고들지 않음.
- **브랜드/사이즈 체크박스 접근성 이름의 대소문자 불일치**: CSS `text-transform:uppercase`로 화면엔 대문자(예: "LULULEMON", "DIOR")로 보이지만 실제 DOM 텍스트는 혼합 대소문자(예: "Lululemon")라 `exact:true` 매칭이 실패함(TC_PD_033, TC_PD_041에서 재현). → **조치**: 대소문자 무시 정규식으로 변경.
- **체크박스를 연속으로 check() 호출하면 먼저 체크한 항목이 리렌더링 중 일시적으로 풀림**: TC_PD_035에서 재현(S 체크 → M 체크 후 S가 unchecked로 관측). → **조치**: 각 체크 사이에 대기 시간 추가.
- **가격 슬라이더(`input[type=range]`)의 `fill()`은 `step` 속성에 맞지 않는 값을 주면 "Malformed value" 오류**: TC_PD_041에서 `step=10000`인데 `1000`을 넣어 실패. → **조치**: step에 맞는 값(10000)으로 수정.
- **TC_PD_119의 TC 원문 링크 텍스트("자주하는질문")가 실제 화면 표기("자주묻는질문")와 다름**: 사이트 결함이 아니라 TC 문서 작성 시점의 표기 차이로 판단. → **조치**: 두 표기 모두 허용하는 정규식으로 테스트 수정(사이트/결함 변경 아님).
- **TC_PD_113의 최초 로케이터가 실제 결함을 가려서 거짓으로 통과함**: `ancestor::a[1]`는 텍스트 자신이 `<a>`인 경우(self)를 못 찾아 `href=null`을 반환, `expect(null).not.toBe('')`가 무조건 통과. → **조치**: `ancestor-or-self::a[1]`로 수정해 실제 `href=""` placeholder 상태가 드러나도록 함 → DEF_데모사이트_017로 등록.
- **TC_PD_101이 표준 DEF_007 서명(naver/google/3top 404) 외에 `/service`, `/forgot-password`, `/policy` 404도 함께 유발**: 비로그인 위시리스트 클릭이 로그인 관련 페이지들을 프리페치하는 것으로 추정. 신규 결함으로 별도 등록하지 않고 DEF_데모사이트_001(위시리스트→로그인 흐름 404)과 같은 근본원인 계열로 묶어 N/T 처리(20-7항 "같은 근본원인" 해석 적용). 필요시 별도 결함으로 분리해도 됨.
- **TC_PD_041(Empty State 결함, DEF_데모사이트_014)의 재현이 매번 100% 결정적이지 않음**: `if (count===0) { assert 안내문구 }` 구조라, 필터 조합이 그날 카탈로그 상태에 따라 우연히 0건이 안 나오면 검증 없이 통과(공허한 Pass)해버림. 실제 결함(빈 화면에 안내문구 없음)은 수동 재현으로 명확히 확인했으나, 자동화 테스트 자체의 신뢰도는 낮음. → 후속 개선 권장: 0건을 항상 강제하는 방식(예: 존재하지 않는 조합 사용)으로 테스트 보강.
- **DEF_데모사이트_007(배너 프로토콜 누락 404)이 열려있는 동안, 메인(`/`) 페이지를 거치는 모든 자동화 테스트는 원천적으로 깨끗한 Pass를 받을 수 없음**: `_shared/testFixtures.js`에 알려진/허용 오류를 걸러내는 allowlist 메커니즘이 없어서, 자체 어서션이 통과해도 픽스처가 강제로 실패 처리함. 이번 45건 중 20건(N/T-007) + 기존 여러 TC가 이 구조적 제약을 받는다. 결함이 아니라 테스트 프레임워크의 한계이므로, 향후 "알려진 결함 화이트리스트" 기능 추가를 고려할 만함(이번 범위 밖).
- **PD.html/전체.html 뷰어 재생성 시 발견한 이스케이프 버그**: TC_PD_045(XSS 안전성 검증 TC)의 `steps`/`testData` 필드에 리터럴 `<script>alert(1)</script>` 문자열이 포함되어 있는데, 뷰어 재생성 스크립트를 쉘(bash) 명령 안에 인라인으로 작성했을 때 백슬래시 다중 이스케이프가 뒤틀려 `<` → `<` 치환이 실제로는 적용되지 않는 사고가 있었다(뷰어의 `<script>` 블록이 조기 종료되어 JS 파싱 에러 발생). → **조치**: 치환 로직을 쉘 인라인 대신 별도 `.js` 파일로 작성해 쉘 이스케이프 문제를 원천 차단, 재실행 후 두 뷰어 모두 브라우저에서 JS 에러 없이 정상 렌더링되는 것을 확인했다. **교훈**: 앞으로 HTML `<script>` 임베드용 이스케이프 로직은 절대 쉘 커맨드에 인라인으로 작성하지 않고 항상 스크립트 파일로 작성한다.
- **PD.html(및 v14 legacy 원본)에 `<script>` 개수 불일치(open 1 : close 2)가 이전부터 존재**: 실제 파싱/렌더링에는 문제가 없었고(브라우저에서 정상 동작 확인), 정확한 원인(문자열 내 리터럴 `</script>` 등)은 시간상 더 파고들지 않았다. 후속 점검 권장.
