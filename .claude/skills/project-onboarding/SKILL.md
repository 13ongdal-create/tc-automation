# 프로젝트 온보딩 (신규 프로젝트 추가)

1. `tc-automation\_template\`을 `tc-automation\project\{프로젝트명}\`으로 복사합니다 (Policy/SB/Requirements/Analysis/TC 빈 폴더 포함). **다른 기존 프로젝트 폴더를 복사하거나 참고하지 않습니다** — 항상 `_template\`에서만 시작합니다.
2. 고객/기획 측에서 받은 기준문서를 해당 서브폴더에 넣습니다 (정책서→Policy, 화면설계서→SB, 요구사항→Requirements). **`Analysis\`는 고객 제공 문서를 넣는 곳이 아닙니다** — Phase 1~3에서 어시스턴트가 직접 관찰·정리한 산출물(`project\{프로젝트명}\Analysis\{프로젝트명}_PRD.html`)만 여기 저장합니다.
3. 기존에 운영 중이던 레거시 TC가 있다면 `TC\legacy\`에 넣습니다.
4. 이후 TC 생성 요청 시 스킬은 자동으로 **이 프로젝트 자신의** `project\{프로젝트명}\Policy`, `\SB`, `\Requirements`, `\TC\legacy`만을 근거 자료로 스캔합니다 (다른 프로젝트 폴더는 스캔 대상이 아님). `\Analysis\`는 근거 자료가 아니라 이미 정리된 산출물이므로 스캔 대상에서 제외합니다.
5. 프로젝트명은 폴더명과 TC ID 접두, HTML 뷰어 타이틀, 파일명에 일관되게 사용합니다.
6. **최초 TC 생성 요청 시 Phase 0(AGENTS.md 13항)을 수행**하여 `project.json`(URL, 단위/통합 구분, 코드/정책기반)을 생성합니다 — 폴더 복사 시점이 아니라 첫 요청 시점에 사용자 답변을 받아 생성합니다.
7. **노션 동기화 (Notion MCP 도구 접근 가능한 경우)**: Phase 0 완료 직후(project.json 생성 후), 노션 위키 DB `🧪 [자동화] TC 생성 자동화`(https://app.notion.com/p/3b5f3310e03181449b1ad28cf72e9482, 하위 페이지 생성 시 parent는 `page_id`/`database_id`가 아니라 **`data_source_id`**로 지정 — 반드시 먼저 `fetch` 도구로 이 DB URL을 조회해 `<data-source url="collection://...">` 값을 확인한 뒤, `{ type: "data_source_id", data_source_id: "..." }` 형태로 지정합니다. 최상위 `{프로젝트명}` 페이지 생성 시 `properties`의 title 값은 스키마의 실제 타이틀 속성명("페이지")을 키로 사용해야 하며, `title`이라는 키를 쓰면 무시되고 페이지가 무제목으로 생성될 수 있습니다 — 생성 직후 반드시 `fetch`로 제목이 실제로 반영됐는지 확인하고, 비어 있으면 `update-page`의 `update_properties`로 같은 속성명("페이지")을 사용해 재설정합니다.) 아래에 `{프로젝트명}` 페이지를 만듭니다. 그 하위에는 아래 **3종류**의 서브페이지를 생성/관리합니다 (데모사이트 프로젝트에 이미 적용된 구조를 그대로 따름, 2026-08-21 구조 확정). **Notion 도구에 접근할 수 없는 환경이면 이 단계는 건너뛰고, 그 사실을 사용자에게 알립니다** (건너뛴 것 자체를 조용히 넘기지 않음).

   **a. PRD (관찰 기반 요약)** — Phase 0 완료 시 최초 생성. 실제 정책서/화면설계서가 없다면 "공식 문서 아님, Playwright 관찰 기반 요약" 문구로 시작하고, 관찰된 내용만 근거로 작성합니다 (AGENTS.md 7항 근거 원칙 그대로 적용 — 노션이라고 예외 아님). **로컬의 `project\{프로젝트명}\Analysis\{프로젝트명}_PRD.html`이 이 노션 PRD 페이지의 원본(source of truth)입니다** — 로컬 PRD 내용이 갱신되면(사이트 재관찰, 결함 증상 변경 등) 노션 PRD 페이지도 같은 시점에 갱신해 둘을 동기화합니다.

   **b. TC 버전 이력** — Phase 0 완료 시 빈 틀로 최초 생성 후, 모듈이 하나씩 완료될 때마다 그 모듈 섹션을 추가합니다. **이 페이지는 요약/인덱스 전용이며, 모듈별 상세 버전 행 표는 담지 않습니다** (그 표는 c번 페이지 소관):
      - 최상단 "통합(Full) TC 뷰어" 섹션(모듈이 2개 이상일 때만): 뷰어 링크 + Git 원본 경로 (`{프로젝트명}_TC_전체.json`)
      - 모듈별 섹션: "현재 최신: v{N} ({건수}건)" + 해당 모듈 c번 페이지로의 링크만
      - "테스트 결과 이력": Phase 5 실행분을 **개별 TC 행이 아니라 수행날짜×모듈 기준으로 집계**한 표 — 컬럼 순서 `수행날짜 | 모듈 | TC 수행건수 | 결과 | 비고`. "결과"는 `Pass N건 · Fail N건` 형식으로 집계. "비고"에는 확인필요/N/A/N/T가 발생한 경우에만 그 건수와 사유를 기입(발생 없으면 "-")
      - "결함 현황": `defects.json` 전체를 **진행상태(status) 기준으로 그룹**한 표 — 컬럼 순서 `진행상태 | 모듈 | 발견일 | 결함ID | 요약`
      - 노션 표에 넣는 요약 텍스트의 escape 규칙: `[`, `]`, `~`, `>` 등은 반드시 `\[`, `\]`, `\~`, `\>`처럼 백슬래시로 이스케이프합니다. **한글 텍스트를 `\uXXXX` 형태로 손으로 인코딩해서 채우지 않습니다** — 반드시 UTF-8 원문 그대로 파라미터에 작성합니다(손 인코딩 시 오타로 내용이 깨진 사례 있음, 2026-08-21).

   **c. TC 목록 ({모듈 한글명}/{코드})** — 모듈별로 1개씩, Phase 4(해당 모듈 TC 작성) 완료 후 생성합니다. **개별 TC 행을 나열하는 표는 두지 않습니다** — 뷰어가 이미 전체 TC를 상세히 보여주므로 중복입니다. 구성:
      - 안내 문구(버전/건수) + **뷰어** 링크 + **Git 원본** 경로(`{프로젝트명}_TC_{모듈코드}.json`)
      - 그 아래 이 모듈의 **버전 이력 표**(버전/날짜/건수/요약, `meta.changeHistory` 미러링). **버전이 새로 올라갈 때마다(AGENTS.md 10항 파일 버전관리 시점) 이 표에 새 행을 추가**합니다 — b번 "TC 버전 이력" 페이지가 아니라 **이 페이지**에 추가하는 것에 주의합니다.
      - 필요 시 관련 결함 참고 문구(`> 결함 참고: ...`)

   **뷰어 링크 발행**: a~c 어디든 "뷰어" 링크가 필요하면, 로컬 HTML 뷰어 파일(개별 모듈 또는 `_전체`)을 Artifact 도구로 발행해 얻은 URL을 사용합니다. **발행된 Artifact는 기본적으로 비공개**이므로, 팀원 공유가 필요하면 사용자에게 아티팩트 페이지의 공유 메뉴에서 직접 공개로 전환해야 한다는 점을 안내합니다. 뷰어 내용이 크게 바뀌면(모듈 재구성, 대규모 배치 등) 같은 `file_path`로 재발행해 링크(URL은 유지됨)를 최신화하되, 매 소규모 TC 수정마다 재발행할 필요는 없습니다 — Git 원본이 항상 최신 기준이므로 뷰어가 다소 지연돼도 무방합니다.

   **노션 도구 사용 시 알아두면 좋은 특성 2가지** (2026-08-27 확인):
   - **DB 홈 페이지 본문을 `fetch`로 읽으면 스키마만 나오고 본문 내용은 안 보일 수 있습니다** (이 DB
     홈처럼 표 위/아래에 일반 텍스트 섹션이 있는 "wiki 데이터베이스"에서 재현). 이럴 때는 `search`
     도구를 `content_search_mode: "ai_search"`로 호출하면(`type: "block"`으로 잡힘) 본문 스니펫이
     실제로 조회됩니다 — 여러 키워드로 나눠 검색해 조각을 모으면 전체 내용을 재구성할 수 있습니다.
   - **`update-page`의 `update_content`(search-and-replace)로 표(`<table>`) 셀을 수정할 때, `old_str`에
     완전한 `<tr>...</tr>` 블록 또는 태그 없는 순수 텍스트만 넣으면 매칭에 성공하지만, `<td>`가 중간에
     여닫히지 않고 잘린 조각(예: 여러 줄짜리 `<tr>` 중 앞부분만)을 넣으면 "다른 들여쓰기" 오류로
     실패합니다.** 실제 저장 형식은 각 `<td>` 줄 앞에 탭(`\t`) 들여쓰기가 있습니다 — 표를 통째로
     바꾸려면 `<tr>`부터 `</tr>`까지 탭 들여쓰기를 맞춰 완전한 블록으로 넣고, 셀 안 텍스트 일부만
     바꾸려면 태그 없이 순수 텍스트 구간만 `old_str`로 지정하는 편이 안전합니다.
